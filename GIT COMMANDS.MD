# 📝 Шпаргалка по Git: Создание и управление репозиторием

## 🚀 1. Инициализация проекта и первая фиксация

| Команда | Описание |
| :--- | :--- |
| `git init` | Превратить текущую папку в Git-репозиторий (создает скрытую папку `.git`). |
| `git status` | Проверить состояние файлов (какие изменены, какие еще не отслеживаются). |
| `git add .` | Добавить **все** измененные и новые файлы в индекс (подготовить к сохранению). |
| `git add <файл>` | Подготовить к сохранению конкретный файл. |
| `git commit -m "текст"` | Сохранить изменения (создать снимок/слепок проекта с комментарием). |

---

## 🔍 2. Проверка состояния и поиск изменений (Диффы)

| Команда | Описание |
| :--- | :--- |
| `git status` | Главный инструмент для проверки текущего статуса репозитория. |
| `git diff` | Показать, что конкретно изменилось в файлах по сравнению с последним коммитом. |
| `git diff --staged` | Показать изменения в файлах, которые уже добавлены в индекс через `git add`. |
| `git log` | Посмотреть историю всех коммитов в текущей ветке. |
| `git log --oneline` | Компактный просмотр истории коммитов (один коммит — одна строка). |

---

## 🌿 3. Работа с ветками (Бранчевание)

| Команда | Описание |
| :--- | :--- |
| `git branch` | Показать список всех локальных веток в проекте. |
| `git branch <ветка>` | Создать новую ветку (но не переключаться на нее). |
| `git checkout <ветка>` | Перейти на указанную ветку. |
| `git checkout -b <ветка>`| Создать новую ветку и **сразу** переключиться на нее (самый частый вариант). |
| `git merge <ветка>` | Объединить указанную ветку с текущей (нужно быть в ветке, куда вливаем). |
| `git branch -d <ветка>` | Удалить ветку после того, как она была успешно объединена. |

---

## ☁️ 4. Работа с удаленным сервером (GitHub / GitLab)

| Команда | Описание |
| :--- | :--- |
| `git remote add origin <url>`| Связать локальный репозиторий с пустым удаленным репозиторием в облаке. |
| `git push -u origin main` | Отправить код в облако в первый раз (и связать ветку `main` с удаленной). |
| `git push` | Отправить новые коммиты в облако (все последующие разы). |
| `git pull` | Скачать свежие изменения из облака и сразу объединить их со своей версией. |
| `git fetch` | Проверить, появились ли изменения в облаке, без скачивания их в файлы. |
| `git clone <url>` | Полностью скопировать существующий удаленный репозиторий на компьютер. |

## 🛠️ 5. Продвинутые и редкие сценарии (Продвинутый уровень)

| Команда / Сценарий | Описание |
| :--- | :--- |
| **Перенос точечных изменений** | |
| `git cherry-pick <id_коммита>` | **Скопировать конкретный коммит** из любой ветки в вашу текущую ветку (идеально для переноса одиночной фичи или хотфикса). |
| **Смена базовой ветки** | |
| `git rebase <имя_ветки>` | Перенести всю цепочку ваших коммитов так, будто вы начали делать их поверх самой свежей версии указанной ветки (делает историю линейной). |
| **Временный карман (Прятанье кода)** | |
| `git stash` | **Спрятать незавершенные изменения** в "карман" и очистить рабочую зону (когда нужно срочно переключить ветку, но коммитить недоделки не хочется). |
| `git stash pop` | Достать обратно из "кармана" ваши последние спрятанные изменения и продолжить работу. |
| `git stash list` | Посмотреть список всех отложенных в "карман" изменений. |
| **Исправление на месте** | |
| `git commit --amend -m "новый текст"`| Добавить текущие незакоммиченные правки в **самый последний коммит** или просто изменить его текст (чтобы не плодить лишние мелкие коммиты). |

## ⏪ 6. Отмена изменений и откат (Спасательный круг)

| Команда | Описание |
| :--- | :--- |
| `git restore <файл>` | Отменить все незакоммиченные изменения в конкретном файле. |
| `git restore .` | Отменить **вообще все** незакоммиченные изменения в текущей папке. |
| `git reset HEAD~1 --soft`| Отменить последний коммит, но оставить все изменения в файлах для правок. |
| `git reset --hard <id>` | Жестко откатить весь проект к коммиту `<id>` (все изменения после сотрутся!). |

## 📋 7. Примеры работы (Сценарии)

### 🟢 7.1 Простой сценарий: Базовый workflow
*Типичный цикл: правки → проверка → коммит → мердж в main*

```bash
# 1. Проверяем текущее состояние
git status

# 2. Смотрим, что конкретно изменилось (до add)
git diff

# 3. Добавляем все изменения в индекс
git add .

# 4. Проверяем, что попало в индекс (staged)
git diff --staged

# 5. Коммитим с понятным сообщением
git commit -m "feat: добавить авторизацию пользователя"

# 6. Проверяем историю
git log --oneline -5

# 7. Переключаемся на main
git checkout main

# 8. Подтягиваем актуальное состояние (если работаем в команде)
git pull origin main

# 9. Вливаем нашу ветку в main
git merge feature/auth

# 10. Пушим в удалённый репозиторий
git push origin main

# 11. Удаляем ненужную ветку локально
git branch -d feature/auth
```

### 🔴 7.2 Комплексный сценарий: Продвинутый workflow
*Полный цикл с откатами, amend, cherry-pick, точечными правками*

```bash
# === НАЧАЛО РАБОТЫ ===
git checkout main
git pull origin main
git checkout -b feature/payment-integration

# === РАБОТА: первый подход (черновик) ===
# ... правим файлы ...
git add .
git commit -m "wip: набросок оплаты"  # черновик, можно не пушить

# === РАБОТА: доработка, хотим поправить последний коммит ===
# ... делаем правки в коде ...
git add payment.ts
git commit --amend -m "feat: интеграция Stripe для оплаты"

# === ОШИБКА: закоммитили не то / лишнее ===
git reset HEAD~1 --soft    # отменили коммит, изменения остались в staged
git restore --staged config.json  # убрали config.json из коммита
git commit -m "feat: интеграция Stripe для оплаты"  # перекоммитили без конфига

# === АЛЬТЕРНАТИВА: коммит через файл (для длинных сообщений) ===
git commit -F commit-message.txt
# где commit-message.txt содержит:
# feat: интеграция Stripe
#
# Добавлена поддержка оплаты картами через Stripe.
# Включены вебхуки для подтверждения платежей.
# Closes #42

# === ПЕРЕКЛЮЧЕНИЕ КОНТЕКСТА (нужно срочно пофиксить баг в main) ===
git stash                    # спрятали текущие незакоммиченные правки
git checkout main
git checkout -b hotfix/login-bug
# ... фиксим баг ...
git add .
git commit -m "fix: исправить вход через Google OAuth"
git checkout main
git merge hotfix/login-bug
git push origin main
git branch -d hotfix/login-bug

# === ВОЗВРАЩАЕМСЯ К СВОЕЙ ЗАДАЧЕ ===
git checkout feature/payment-integration
git stash pop                # достали правки обратно

# === СЛИЯНИЕ С MAIN (rebase для чистой истории) ===
git fetch origin
git rebase origin/main       # переносим свои коммиты поверх свежего main
# если конфликты — решаем, потом:
git add .
git rebase --continue

# === ТОЧЕЧНОЕ ПРИМЕНЕНИЕ ИЗМЕНЕНИЙ ИЗ ДРУГОЙ ВЕТКИ (cherry-pick) ===
# Нужно взять только коммит с рефакторингом уведомлений из ветки feature/notifications
git log feature/notifications --oneline
# a1b2c3d refactor: вынести уведомления в сервис
git cherry-pick a1b2c3d

# === ФИНАЛЬНАЯ ПРОВЕРКА ПЕРЕД ПУШЕМ ===
git log --oneline -10        # проверяем историю
git diff origin/main         # смотрим полный дифф относительно main

# === ПУШ С ФОРСОМ (если делали rebase/amend на уже запушенной ветке) ===
git push origin feature/payment-integration --force-with-lease

# === ПОСЛЕ CODE REVIEW: мелкие правки ===
# ... правки по комментариям ревьюера ...
git add .
git commit --amend --no-edit  # добавляем в последний коммит без изменения сообщения
git push origin feature/payment-integration --force-with-lease

# === МЕРДЖ В MAIN (через PR или локально) ===
git checkout main
git pull origin main
git merge --no-ff feature/payment-integration  # --no-ff сохраняет историю ветки
git push origin main
git branch -d feature/payment-integration
```

### 📌 7.3 Шпаргалка по выбору стратегии

| Ситуация | Команда | Примечание |
|----------|---------|------------|
| Хочу чистую линейную историю | `git rebase main` | Только для локальных веток! |
| Хочу сохранить историю ветки | `git merge --no-ff feature` | Создаёт merge-коммит |
| Нужен только один коммит из чужой ветки | `git cherry-pick <hash>` | Точечное копирование |
| Срочно переключиться, не коммитя | `git stash` / `git stash pop` | Временное хранилище |
| Исправить последний коммит | `git commit --amend` | Не делайте после push без force |
| Отменить коммит, оставить правки | `git reset HEAD~1 --soft` | Мягкий откат |
| Жёстко откатить к состоянию | `git reset --hard <hash>` | ⚠️ Данные пропадут навсегда |
